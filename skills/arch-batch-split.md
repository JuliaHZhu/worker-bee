# 批量原子切割

无交互、全自动。输入文本 → 切原子 → 写文件 → 报告完成。

## 存储位置

```
~/.worker-bee/arch/texts/<name>/
└── atoms.md      ← 原子列表（带字数，标签标为 [待打]）
```

## 输入方式

| 方式 | 怎么做 |
|------|--------|
| **URL** | 用户给一个或多个 URL → `net_web_extract` 提取 → 逐个切 |
| **本地文件** | 用户给路径 → `fs_read_file` 读 → 切 |
| **粘贴文本** | 用户直接粘贴 → 先写入 `source.md` → 再切 |
| **批量** | 用户给一个目录或多个 URL → 逐个处理，不等待 |

## 切割规则

| 体裁 | 原子定义 |
|------|---------|
| 小说 | 同一场景内连续对话 = 1原子；场景切换/视角切换/时间跳跃 = 新原子 |
| 论文 | 一个自然段 = 1原子 |
| 申论 | 一个自然段 = 1原子 |

体裁由用户指定（"按小说切"/"按论文切"/"按申论切"）。未指定时按自然段切。

## 输出格式

atoms.md：

```markdown
# Atoms: <name>
## 体裁: 小说 | 论文 | 申论
## 总原子数: <N>
## 标签完成: 否

### Chunk 1: <章节名或分段标记>

#001 [待打] [字数]
<原文>

#002 [待打] [字数]
<原文>
```

## 完成后报告

```
✓ 已切: <name>
  体裁: 小说
  原子数: 847
  总字数: 124,500
  平均原子长: 147字
  存储: ~/.worker-bee/arch/texts/<name>/atoms.md
  
  下一步: "打标签" 启动 Phase 2
```

## 批量模式示例

用户说 "批量切这三篇 https://... https://... https://...，都按小说切"

→ 逐个提取 → 逐个切 → 全部完成后报告：

```
✓ 三体-第一章: 124原子 / 18,600字
✓ 三体-第二章: 98原子 / 14,200字
✓ 三体-第三章: 156原子 / 22,800字
```

## 约束

- 不提问——体裁没指定就按自然段切，不回头确认
- 每篇切完立即写 atoms.md，不攒在内存
- 单个文件超过 2000 原子时分段写（先写前 2000，追加后续）
- 名字自动从 URL 标题或文件名取，取不到时用 `untitled-N`
- 同名文件不覆盖——加序号后缀（`atoms-2.md`）
