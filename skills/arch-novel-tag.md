# 小说引擎标签系统

所有可用标签就是你的 **Deck**。读原子 → 看 Deck 里的标签定义 → 挑最匹配的 1-3 个贴上。不打多，不打勉强。

## 存储位置

arch-novel-tag 在同一目录读写：

```
~/.worker-bee/arch/texts/<作品名>/<段-slug>/
├── source.md          ← 原文（只读，不修改）
└── atoms.md           ← 输入: 未标原子 → 输出: 已标原子（原地更新）
```

- **输入**: `atoms.md`，原子标记为 `[待打]`
- **输出**: 同一个 `atoms.md`，`[待打]` 替换为引擎标签
- 更新文件头: `标签完成: 否` → `标签完成: 是`
- source.md 只读参考，不修改

## 标签 Deck（10 张牌）

| 标签 | 含义 | 判断标准 |
|------|------|---------|
| **线索** | 指向真相的信息碎片 | 删掉后读者少一条推理路径。可以是物品、对话中的信息、环境细节 |
| **误导** | 故意引向错误方向 | 删掉后读者不会被骗。看起来像线索，其实是障眼法 |
| **张力** | 紧迫感/威胁升级 | 有时间压力（倒计时）、威胁逼近、或 stakes 在升高 |
| **揭示** | 部分真相浮出 | 读者发出"原来如此"的时刻。揭示 ≠ 线索——线索是碎片，揭示是拼上 |
| **动机** | 人物为什么这么做 | 行为的心理原因暗示。可以是对话、回忆、或他人转述 |
| **手法** | 怎么做到的 | 犯罪手法/行动方式的暗示或展示。和动机分开——一个是 why，一个是 how |
| **人物** | 人物建立/关系推进 | 纯粹塑造人物弧线、展示关系变化。不推进主线谜题 |
| **场景** | 环境/氛围建立 | 纯空间描写/气氛营造。不携带线索信息 |
| **转折** | 预期被推翻 | 读者以为 A 结果是 B。和揭示的区别：揭示是拼上拼图，转折是掀桌子 |
| **收束** | 解谜/回扣/填坑 | 前面埋的伏笔在这里兑现。故事的"扣环"闭合点 |

## 打标签流程

1. 读 `~/.worker-bee/arch/texts/<name>/atoms.md`
2. 按 `[待打]` 定位未标注原子，每批处理 200 个
3. 对每个原子：读原文 → 对照 Deck 定义 → 挑 1-3 个标签
4. 更新：`[待打] [180字] [对话]` → `[线索] [动机] [180字] [对话]`
5. 重复到全部打完 → 更新文件头 `标签完成: 是`

## 标注示例

```
原文:
"你等了多久了？"
"三个钟头。他没出来过。"
"不可能。后门呢？"
"堵死的。"
老张把烟头捻灭在墙上，火星溅了他一手。他没躲。

→ [张力] [线索] [对话]
理由: "三个钟头"制造时间压力(张力)；"后门堵死的"是信息碎片(线索)。
      不标人物——这段推进的是谜题，不是人物弧线。
```

```
原文:
他想起二十年前第一次见到她。也是冬天，也是这条胡同。
她穿着红棉袄，在雪地里像一团火。

→ [人物] [描写-场景]
理由: 纯回忆+人物关系建立，不推进主线。不标线索——这只是情感背景。
```

## 标注原则

- **主功能优先**：一段里 80% 在制造张力，20% 带点人物 = 标 `[张力]`，不标 `[人物]`
- **宁可漏，不要强**：拿不准的标 `[其他]`
- **1-3 个，绝大多数是 1-2 个**：不要为了凑数硬贴
- **对话 ≠ 自动标人物**：对话可以标线索/误导/动机/张力/揭示。人物标签只在纯粹塑造角色时用
- **注意标签互斥**：
  - `[线索]` vs `[误导]` — 是真相还是障眼法？只能二选一
  - `[揭示]` vs `[转折]` — 是拼上拼图还是掀桌子？只能二选一
  - `[动机]` vs `[手法]` — 是 why 还是 how？可以同时标，但一般不同时出现

## 完成后更新

打完所有标签后，更新 atoms.md 头部：

```markdown
# Atoms: <name>
## 体裁: 小说
## 总原子数: 847
## 标签完成: 是
```

然后告诉用户：
```
✓ 标签完成: <name>
  847 原子全部标注
  
  标签分布预览（抽查前100原子）:
  线索 22% / 张力 18% / 对话 35% / 人物 15% / 揭示 5% / 其他 5%
  
  下一步: "看统计" → arch-atomic-analysis Phase 3
```
