Product Requirements Document

Problem Statement

Worker Bee 的 Deck 机制声称实现"物理隔离"——通过 Skill 声明的工具集来限制 Agent 的能力范围，使其专注于特定工种。但当前实现中，main.py 无条件地将 config.tools 中的所有工具（terminal、file read/write/search、web、delegate 等 9 个工具）合并到每个 Deck 中。

这导致：

  • 无论 Skill 声明了什么工具，Agent 始终能访问所有 config.tools
  • "物理隔离"名存实亡，Deck 成为一个"半透膜"
  • 用户无法通过 Skill 声明来真正限制 Agent 的工具范围
  • BASELINE_POOL 的冗余机制形同虚设

Solution

引入双模式 Deck 系统：

  1. 全工具模式（默认）：Agent 可访问 config.tools 中的所有工具，适合探索、闲聊、多任务切换
  2. Deck 专注模式：Agent 仅能使用 trigger 匹配的 Skill 声明的工具 + 基础冗余工具，实现真正的物理隔离

用户通过 wb deck CLI 在两种模式间切换，Agent 也可以通过 sys_terminal 工具调用 CLI 实现自主切换。

User Stories

  1. 作为 Worker Bee 用户，我希望默认情况下 Agent 能访问所有工具，这样我不需要手动配置就能完成大部分任务
  2. 作为需要专注执行特定工种的用户，我希望能切换到 Deck 专注模式，让 Agent 只使用与当前任务相关的工具
  3. 作为用户，我希望在 Deck 专注模式下，Agent 因工具不足无法完成任务时能明确告诉我原因和解决方法
  4. 作为用户，我希望能通过 wb deck add <tool> 临时向当前 Deck 添加工具，而不必切回全工具模式
  5. 作为用户，我希望能通过 wb deck drop <tool> 从当前 Deck 移除工具
  6. 作为用户，我希望能通过 wb deck reset 清空当前 Deck 并重新触发 Skill 匹配
  7. 作为用户，我希望能通过 wb deck list 查看当前 Deck 中包含哪些工具
  8. 作为用户，我希望能通过 wb deck mode 查看当前处于哪种模式
  9. 作为用户，我希望能通过 wb deck log 查看 Deck 使用统计，了解我最常用的工具组合
  10. 作为 Skill 作者，我希望在 Deck 专注模式下，我声明的工具集能真正限制 Agent 的能力范围
  11. 作为 Agent，我希望在 Deck 专注模式下无法完成任务时，能通过 sys_terminal 调用 wb deck add <tool> 请求添加工具
  12. 作为 Agent，我希望能通过 deck_manage Tool 查询当前 Deck 状态
  13. 作为 Agent，我希望在 Skill 中学习到什么情况下该切换 Deck 模式

Implementation Decisions

核心架构决策

  • 双模式设计：全工具模式（默认）+ Deck 专注模式，由用户/Agent 主动切换
  • 默认全工具模式：新用户/新会话默认使用全工具模式，降低学习成本
  • trigger 匹配后锁定：Deck 专注模式下，首次 trigger 匹配后锁定，不自动重匹配（除非手动 wb deck reset）
  • fallback 最小集：Deck 专注模式下无 Skill 匹配时，使用最小工具集（fs_read_file、fs_search_files、sys_terminal）

main.py Deck procurement 逻辑改动

将原有的无条件合并逻辑改为双模式分支：

if deck_mode == "full":
    # 全工具模式：config.tools 全量
    deck = Deck(config.get("tools", []), registry)
else:
    # Deck 专注模式：
    # 1. 首次 trigger 匹配后锁定，不自动重匹配
    # 2. 无 skill 匹配 → fallback 最小集
    if not skill_tools:
        fallback = ["fs_read_file", "fs_search_files", "sys_terminal"]
        deck = Deck(fallback, registry)
    else:
        deck = build_deck(skill_tools, registry, redundancy=3)

final_tools = infra.filter_tools(deck.tools)
deck = Deck(final_tools, registry)

CLI 设计

新增 wb deck 子命令组：

  • wb deck mode — 查看当前模式
  • wb deck full — 切全工具模式
  • wb deck focus — 切 Deck 专注模式
  • wb deck add <tool> — 往当前 Deck 加工具
  • wb deck drop <tool> — 从当前 Deck 移除工具
  • wb deck reset — 清空 Deck，重新 trigger 匹配
  • wb deck list — 列出当前 Deck 里的工具
  • wb deck log — 查看 Deck 使用统计

Tool 层设计

新增 deck_manage Tool，薄执行层，对应 CLI 的各个操作：

  • mode / switch / add / drop / reset / list / log
  • Agent 通过 sys_terminal wb deck <cmd> 或直接调用 deck_manage Tool

Skill 层设计

新增 deck-control Skill（meta skill），教 Agent：

  • 什么时候该切换模式
  • Deck 专注模式下无法完成任务时的标准回复模板： 
    我做不到：[原因]
可行做法：用 wb deck add <tool> 加工具，或 wb deck full 切回全工具模式。

Deck Log 设计

JSON 文件：~/.worker-bee/deck_log.json，记录：

  • combos：工具组合使用统计（count + last_used）
  • mode_switches：模式切换次数
  • focus_sessions：Deck 专注模式会话数

长期可用于自动推荐 Deck 组合。

config.tools 的新角色

config.tools 保留，但角色调整为：

  1. 全工具模式的 Deck 来源
  2. 注册表查询（/tools 命令）
  3. Skill 声明校验（加载时检查 tool 名是否存在）
  4. 不再注入 Deck 专注模式的 Deck

三层封装

层级名称职责
CLIwb deck人类快捷键——终端直接操作
Tooldeck_manage薄执行——mode/switch/add/drop/reset/list/log
Skilldeck-control推理手册——什么时候该切换模式、"做不到"时的回复模板

不用 Deck 功能时关掉 deck-control skill → Deck 不再装填 deck_manage tool → 物理隔离。

Testing Decisions

测试原则

  • 只测试外部行为，不测试内部实现
  • 测试模块：worker_bee/deck.py、cli.py、tools/deck_manage.py
  • 参考现有测试：tests/test_deck.py、tests/test_agent.py

测试场景

  1. 全工具模式：验证 Deck 包含 config.tools 中的所有工具
  2. Deck 专注模式 + Skill 匹配：验证 Deck 仅包含 Skill 声明的工具 + 冗余
  3. Deck 专注模式 + 无匹配：验证 Deck 使用 fallback 最小集
  4. 模式切换：验证 wb deck full / focus 切换后 Deck 内容正确
  5. 工具增删：验证 wb deck add / drop 修改 Deck 内容
  6. reset：验证 wb deck reset 清空 Deck 并重新匹配
  7. log 记录：验证 deck_log.json 正确记录 combos / mode_switches / focus_sessions
  8. Agent 回复：验证 Deck 专注模式下 Agent 因工具不足无法完成任务时的回复格式

Out of Scope

  • 自动推荐 Deck 组合：需要积累足够的 log 数据，本次只实现 log 记录
  • 更细粒度的权限控制：如工具参数级别的限制
  • Deck 模板保存：用户自定义 Deck 组合并保存为模板

Further Notes

核心理念：全工具模式做日常，Deck 专注模式做工种。config.tools 是注册表，不再是底牌。Tool/Skill/CLI 三层封装，不用就关掉。

向后兼容：默认全工具模式，现有用户/会话无需改动。
