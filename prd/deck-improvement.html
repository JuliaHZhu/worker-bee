Deck 改进方案

让 Deck 真正成为物理隔离,而非半透膜

相关文档: Deck 改进方案 PRD

一、当前问题

症状：Deck 声称"物理隔离"，但实际每次请求 Agent 都能看到全部 config.tools（terminal、file read/write/search、web、delegate × 3），无论匹配了什么 Skill。

根因：main.py 第 528 行无条件合并了 config.tools：

# 第 528 行 — 罪魁祸首
base_tools = config.get("tools", [])
merged_tools = list(dict.fromkeys(deck.tools + base_tools))
deck = Deck(merged_tools, registry)

这导致：

  • Skill 声明 [feishu_lark] → Deck 实际包含 feishu_lark + 全部 9 个 config tools
  • BASELINE_POOL 的 3 冗余槽形同虚设——config.tools 已经全量注入
  • Agent 永远能调 terminal、读写文件、搜索网页，无论 Skill 声明了什么

二、双模式设计

全工具模式 默认Deck 专注模式
Deck 内容config.tools 全量trigger 匹配的 skill_tools + 基础冗余
trigger 匹配不触发每次输入重新匹配 → 锁定
自动重匹配—不自动。手动 wb deck reset
适用场景探索、闲聊、多任务切换专注执行一个工种

默认全工具模式。新用户进来就能用所有东西。需要专注执行某个工种时主动切 Deck 专注模式。

三、代码改动

main.py — Deck procurement 段

# === 改前 ===
deck = build_deck(skill_tools, registry, redundancy=3)
base_tools = config.get("tools", [])
merged_tools = list(dict.fromkeys(deck.tools + base_tools))
final_tools = infra.filter_tools(merged_tools)
deck = Deck(final_tools, registry)

# === 改后 ===
if deck_mode == "full":
    # 全工具模式：config.tools 全量
    deck = Deck(config.get("tools", []), registry)
else:
    # Deck 专注模式：
    # 1. 首次 trigger 匹配后锁定，不自动重匹配
    # 2. 无 skill 匹配 → fallback 最小集
    if not skill_tools:
        fallback = ["fs_read_file", "fs_search_files", "sys_terminal"]
        deck = Deck(fallback, registry)
    else:
        deck = build_deck(skill_tools, registry, redundancy=3)

final_tools = infra.filter_tools(deck.tools)
deck = Deck(final_tools, registry)

效果对比

场景全工具模式Deck 专注模式
匹配 lark-messaging 全部 9 个 config tools feishu_lark + fs_read + fs_search + terminal
无 skill 匹配 全部 9 个 config tools fs_read + fs_search + terminal

四、Agent "做不到" 时的回复规范

Deck 专注模式下 Agent 可能因工具不足而无法完成任务。回复格式：

我做不到：[原因]
可行做法：用 wb deck add <tool> 加工具，或 wb deck full 切回全工具模式。

这个行为写入 meta skill（deck-control），由 Skill 教给 Agent，不是硬编码。

五、wb deck CLI

唯一入口——人在终端敲，Agent 在飞书里通过 sys_terminal 调。

wb deck mode          # 查看当前模式
wb deck full           # 切全工具模式
wb deck focus          # 切 Deck 专注模式，trigger 匹配当前输入或下次输入
wb deck add <tool>     # 往当前 Deck 加工具
wb deck drop <tool>    # 从当前 Deck 移除工具
wb deck reset          # 清空 Deck，重新 trigger 匹配
wb deck list           # 列出当前 Deck 里的工具
wb deck log            # 查看 Deck 使用统计

七、Tool / Skill 封装

Deck 操作按 Worker Bee 哲学封装：

层级名称职责
CLIwb deck人类快捷键——终端直接操作
Tooldeck_manage薄执行——mode/switch/add/drop/reset/list/log
Skilldeck-control推理手册——什么时候该切换模式、"做不到"时的回复模板

不用 Deck 功能时关掉 deck-control skill → Deck 不再装填 deck_manage tool → 物理隔离。

八、飞书菜单 UI（远期）

飞书渠道上可以有一个交互式菜单 Tool，把 wb deck 的操作用卡片/按钮暴露出来——模式切换、工具增减、log 查看。人和 Agent 都能通过飞书界面操作 Deck，不依赖终端。

终端飞书
人类wb deck focus飞书卡片菜单按钮
Agentsys_terminal wb deck add飞书菜单 UI Tool

九、config.tools 的新角色

config.tools 保留，角色调整：

  1. 全工具模式的 Deck 来源
  2. 注册表查询：/tools 命令列出可用工具
  3. Skill 声明校验：加载时检查声明的 tool 名是否在注册表中存在
  4. 不再注入 Deck 专注模式的 Deck
